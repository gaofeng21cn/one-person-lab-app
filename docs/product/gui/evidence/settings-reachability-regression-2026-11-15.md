# 设置入口迁移回归：微信与远程连接

Owner: `one-person-lab-app`
Date: `2026-11-15`
Scope: 源码修复与本机当前 projection 排查；不作为已安装或已发布版本的验收。

## 根因与决策依据

2026-11-08 App `403a1844a1` 为统一扩展安装、启用和更新，将所有包设置贡献归入
包详情，并规定资源页不再挂载它们。统一扩展管理的目标成立；实现把安装管理对象当作功能设置归属，缺少
“远程连接是 App 标准功能”的独立入口约束。

2026-11-10 Studio `62a25cba` 为区分软件与运行组件，将贡献挂载条件从
`item.appEnabled` 收窄为 `item.catalogScope === "software" && item.appEnabled`。
Framework 实际把微信和通用远程伴侣包投影为 `local_component/host_component`。
它们因此进入软件中心的运行组件范围，同时又被组件详情的挂载条件排除。
2026-11-11 App `207c266c86`（PR #366）继续沿用此假设进入软件中心。

原改动的单元验证使用普通软件／独立贡献的 fixture；布局与分类验证没有把当前
运行组件身份接到实际 Settings/详情挂载和动作。部分 source-marker 检查只检查
函数或 JSX 是否存在，无法证明用户能到达它。此次答复最初也犯了同样的错误：从
描述符和安装状态推断可用入口，没有完成页面挂载验证。

## 当前影响核对

2026-11-15 对 `opl app state --profile fast --json` 的新鲜只读回读有 30 项
`settings.section` 贡献，涉及 13 个 Package。原挂载条件按下表审阅：

| 类型 | 当前对象 | 原结果 | 修复 |
| --- | --- | --- | --- |
| 消息通道 | `opl-channel-weixin` | 运行组件详情不挂载，普通软件列表不列出 | 设置中统一配置；组件详情直达 |
| 通用远程伴侣 | `opl-link-desktop-connector` | 同一排除条件 | 同一设置入口；不代替原生 OPL Link |
| 技术活动／诊断 | `opl-fleet-agent` 两项 | activity_log 被普通设置规则排除，组件详情亦无入口 | 启用技术详情后在能力配置的插件组呈现 |
| 其他普通软件设置 | 其余当前软件的服务状态、列表、产物、审批和时间线 | 未命中上述 catalog_scope 排除 | 统一接入能力配置；不声明其业务已逐项验收 |
| 原生 OPL Link／WebUI | Studio Host 面板 | 独立 Settings 路径 | 保留同一连接与部署分组 |

## 修复和防止复发

远程连接按 `channel_access` 和 `remote_companion_access` 的功能语义投影到
设置的“连接与部署 → 远程连接与网页访问”。该分组始终存在，提供者缺失时展示
设置引导；不制造可用连接或虚构安装事实。软件中心继续持有安装、更新与卸载，
远程详情只链接到 Settings。其他已准入设置统一按插件分组接入能力配置，不受软件或运行组件分类影响；折叠时不挂载，技术日志仍受技术详情开关控制。软件中心负责安装管理并跳转到同一设置页。

新增真实 React 挂载与动作测试，覆盖组件身份的远程配置、无提供者的引导、PIN
前导零和提交后读取边界。官方绑定协议测试覆盖 POST 二维码、本人／他人绑定、
PIN 重试、过期／旧挑战、取消和区域重定向。仓库工作约定要求入口迁移在删除旧
入口前验证分类、启停、安装状态下的发现、挂载、读取和操作；不新增固定包白名单。


## 验证结果

App 合同测试 17 项、微信包测试 22 项通过；Studio 新增 5 项真实 React
挂载／交互测试并纳入标准测试入口。`validate:active-shell` 的类型、Node、renderer、
App candidate conformance 与 state-model 所需检查均通过；依赖准备后已通过的 Node
阶段保留证据，renderer 断言修正后从该阶段继续。

Framework 的真实 installed-entrypoint loader 已从本次 `0.2.0` descriptor 加载
微信包，回读四个动作和 dormant/disconnected 状态，未发起真实微信登录。对同一
份当前 projection 重放设置路由：30 项、13 包全部有远程连接设置、能力配置或
用户启用后的技术详情去向，缺失数为 0。

浏览器验证使用当前源码构建的独立交互 fixture，在 1280 px 桌面和 390 px 移动
视口实测 PIN 提交、已连接状态及无提供者引导；无横向溢出，console error 为 0。
这些结果不代表已安装 App 已更新，也不代表真实微信账号扫码或消息收发已验收。
